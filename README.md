# Электронный журнал

Локальный Next.js / React / TypeScript проект с PostgreSQL. Без облачного деплоя.

## Запуск

Открыть **start.cmd** двойным кликом. Скрипт запустит отдельный PostgreSQL,
проверит схему и запустит Next.js на http://localhost:3000.
Окно терминала оставлять открытым. Если браузер открылся раньше готовности сервера, обновить страницу.

Или в PowerShell:

    cd D:\projects\para-journal
    .\start.ps1

При первом переносе на другой компьютер: Node.js, PostgreSQL 18, npm ci,
собственная база и параметры в .env.local; затем npm run db:init и npm run dev.
Скрипт start.ps1 предназначен для локального кластера, созданного на этом компьютере.

## PostgreSQL и pgAdmin 4

Для проекта создан ОТДЕЛЬНЫЙ экземпляр PostgreSQL.
Существующий сервер на 5432 не менялся.

Register → Server:
- Name: Пара — локально
- Host: 127.0.0.1
- Port: 5433
- Maintenance database: para_journal
- Username: gen_user
- Password: указанный вами пароль из .env.local

Данные сервера: .pgdata в каталоге проекта.
Пароль приложения: только .env.local, файл исключён из Git.
База и node_modules также исключены из Git.
Нельзя удалять .pgdata: это данные журнала.

Остановка отдельной базы (после остановки Next.js):

    & "C:\Program Files\PostgreSQL\18\bin\pg_ctl.exe" -D "D:\projects\para-journal\.pgdata" stop -m fast

## Возможности

- Группы и массовая вставка ФИО, по одному студенту на строку.
- Предметы с полным/коротким названием и учебным периодом.
- Общий состав группы во всех журналах.
- Дата зачисления; существующая история выбытия сохранена в базе.
- Таблица и список занятий, без фильтра по тегам.
- Быстрое добавление пары, затем подробная карточка.
- Отметки Н (отсутствие) и О (опоздание). Пустая ячейка не требует отдельного действия.
- Несколько оценок 2–5 за одну пару, включая одинаковые; оценка не заменяет Н/О.
- Оценка и посещаемость независимы: можно сохранить оценку вместе с Н или О.
- Произвольное описание и несколько тегов, включая собственные.
- Меню ячейки по ПКМ или обычному нажатию: оценки 2–5, Н, О и очистка.
- Изменения отметок сохраняются сразу; подробности пары — кнопкой сохранения.

Начните с группы → создайте журнал → добавьте пару.
Один и тот же предмет для двух групп создаётся как два журнала.
В текущей версии нет редактирования/удаления самих групп и названий журналов.

## Проверки

    npm test
    npm run build
    node --env-file=.env.local scripts/smoke-test.mjs

Smoke test требует работающего приложения на 3000, создаёт свои тестовые записи
и удаляет только их. Проверяет общий состав, посещаемость, оценки, теги,
историю выбытия, валидацию и запрет запросов с другого сайта.

## Облако — отдельный следующий шаг

Локальный запуск слушает 127.0.0.1. Страницы и API защищены входом владельца.
Перед размещением в интернете нужно создать или перенести учётку и применить схему авторизации к облачной базе.
Далее можно подключить облачный PostgreSQL через DATABASE_URL либо DB_*,
настроить GitHub → Vercel. Локальная .pgdata на Vercel не переносится.
Полный backup можно сделать
через pgAdmin → para_journal → Backup (формат Custom); восстановление — Restore.

## Интерфейс

Главный экран — каталог всех групп и предметов. Карточка предмета открывает /journals/[id] в текущей вкладке. Нажатие на название группы открывает её первый предмет.
Боковая панель и статистика удалены. Шрифт Inter поставляется локально,
размер текста от 14 px, заголовки 24/28/32/36 px.
Палитра: #fffffe, #094067, #5f6c7b, #3da9fc, #90b4ce, #ef4565.
Кастомные списки и диалоги — Radix UI; анимации — Motion.
Поддерживаются клавиатура, Escape и prefers-reduced-motion.


Карточка занятия содержит только тему, описание, дату и цветные теги с иконками.
Посещаемость и оценки редактируются в таблице через меню ячейки:
5 — зелёный, 4 — синий, 3 — янтарный, 2 — красный, Н — розовый, О — оранжевый.
Меню поддерживает ПКМ, обычное нажатие и клавиатуру.
Экспорт и поле даты выбытия убраны из интерфейса.
Дополнительная проверка опозданий: node --env-file=.env.local scripts/test-late.mjs


## Календарь и компактный журнал

Все даты выбираются через кастомный календарь: месяц/год, день и «Сегодня».
Автозаполнение форм отключено атрибутом autocomplete.
Внутри журнала шапка сайта скрыта: рядом с предметом показана группа,
под названием расположен переключатель предметов этой же группы.
Общий скролл страницы отключён; длинные таблицы, списки и панели
прокручиваются внутри отведённой области.
Поиск студента и нижние подсказки удалены.

Каждое «Поставить 5/4/3/2» добавляет оценку в конец списка.
Н/О отображаются перед оценками. Удалить можно одну оценку по номеру,
все оценки или только Н/О. Действие «Присутствует» в интерфейсе удалено.
Прежние оценки перенесены в список один раз при обновлении схемы.
Новые операции блокируют строку записи при сохранении, чтобы параллельные
добавления из нескольких вкладок не затирали друг друга.

Проверка: node --env-file=.env.local scripts/test-multiple-grades.mjs


## Быстрое заполнение

Кнопка «Быстрое заполнение» над таблицей или иконка в заголовке даты
открывает ввод для одного столбца (одной пары).
Можно переключить пару, отметить Н или О и ввести по одной новой оценке.
Enter переходит к следующему студенту, Shift+Enter — к предыдущему.
Н и О взаимоисключающие. Уже выставленные оценки видны рядом с полем.
Кнопка «Сохранить» добавляет новые оценки к прежним и сохраняет изменённые
отметки одним запросом. При ошибке откатывается весь список.
При закрытии или смене пары с несохранёнными значениями появится подтверждение.

Переходы ускорены на 100 мс. Пункты селектов окрашены в нейтральный цвет.
Контекстные меню ограничены доступной высотой окна и прокручиваются внутри.
Лого — синяя SVG-иконка BookOpenCheck из Lucide.

Проверка быстрого заполнения:
    node --env-file=.env.local scripts/test-quick-fill.mjs


Отображение ячейки: сначала Н или О, затем все оценки.
Повторный выбор установленной Н/О в меню снимает только эту метку.
В заголовке таблицы остались имя столбца и даты, без числа студентов и номера пары.
У пунктов селекта отступ 3 px. Скроллбары в Chromium — 3 px,
с акцентным цветом и прозрачной дорожкой; в Firefox используется тонкий вариант.

## Клавиатура журнала

После выбора ячейки:
- стрелки перемещают между студентами и датами;
- Enter — следующий студент, Shift+Enter — предыдущий;
- 2–5 добавляют оценку, повторные оценки допускаются;
- Н / N и О / O переключают отсутствие/опоздание;
- Escape завершает работу с выбранной ячейкой;
- пробел открывает обычное меню; Tab позволяет выйти из таблицы.

Недоступные ячейки до зачисления/после выбытия пропускаются.
Оценки сохраняются по очереди, чтобы быстрые нажатия не терялись.
Фокус остаётся готовым для следующей клавиши; после мыши нет выделенной рамки.
В быстром заполнении Н/О работают из поля оценки, Enter и стрелки вверх/вниз
переводят фокус по студентам. Сохранение быстрого заполнения — кнопкой «Сохранить».

Иконки 3–5 — BadgeCheck, 2 — CircleAlert.

После обычного клика на ячейку можно сразу нажать цифру или Н/О:
меню закроется, действие сохранится и клавиатурный ввод продолжится в ячейке.

## Репозиторий и база данных

В GitHub хранятся исходники и схема PostgreSQL (scripts/schema.sql).
Существующие студенты, занятия и оценки остаются в локальной базе .pgdata;
пароль остаётся в .env.local. Эти файлы не публикуются.

Для переноса приложения в облако нужна отдельная PostgreSQL:
1. Создать базу и передать её DATABASE_URL через переменные окружения хостинга.
2. Применить scripts/schema.sql к новой базе. Это создаёт таблицы, но не переносит существующие записи.
3. Если нужна текущая история, перенести её отдельно через pg_dump/pg_restore.
   Дамп содержит персональные данные; его не нужно добавлять в GitHub.
4. Применить обновлённую схему и перенести учётку auth_users вместе с данными либо создать её через npm run auth:setup.

Публикация исходников в GitHub сама по себе не запускает сайт и не переносит базу.

## Вход владельца

Логин и scrypt-хеш пароля хранятся в PostgreSQL, таблица auth_users.
Открытого пароля в базе нет. Регистрации через сайт нет; учётка одна.
Приложение не использует AUTH_USERNAME или AUTH_PASSWORD_HASH.
Локальный .auth-owner.txt — только памятка для владельца, а не конфигурация.

Первая настройка после npm run db:init: npm run auth:setup.
Замена пароля: npm run auth:setup -- --reset.
Можно указать --username новый_логин. Утилита работает с базой из DATABASE_URL
или DB_* и отзывает сессии при замене пароля. Существующую учётку без --reset
она не перезаписывает. Смена пароля не требует пересборки приложения.

На Vercel нужны только параметры подключения PostgreSQL. Применить
scripts/schema.sql и перенести auth_users вместе с данными журнала либо
создать владельца утилитой, направив её на новую базу. Автоматической
учётки и публичного создания пользователя нет. Пустая база не пускает в журнал.

Сессия хранится в HttpOnly cookie 7 дней; в production используется Secure
и префикс __Host-. Выход отзывает сессию в базе. Перед выходом ожидающие
отметки сохраняются. Ограничение входа также хранится в PostgreSQL:
10 попыток на адрес за 15 минут и общий предел 60 за 15 минут.

Проверка: node --env-file=.env.local scripts/test-auth.mjs.
Остальные интеграционные тесты создают и удаляют собственную короткую сессию.

Проверка учётки в изолированной временной схеме: node --env-file=.env.local scripts/test-db-owner.mjs.
